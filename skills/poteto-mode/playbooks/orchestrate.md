### Orchestrate

**You run the program, never the code. Decide which agent does each piece of work, then check what each one produces.** For a standing project handed to one coordinator chat: multi-day, many stacked PRs, dozens to hundreds of subagents, few human turns. One task driven to a predicate is Autonomous run. One ambitious run that needs a bespoke workflow is figure-it-out. Work that one agent could finish inside the session's budget is not a program.

Run it with your own tools. Spawn workers through supported Codex subagent tools. Keep the program state in a task checkpoint and an explicit operator-provided state directory; do not infer private host storage. Assign one writer to each state file. Use supported PR and CI event subscriptions only when available and authorized. Do not use the retired orchestration CLI or polling loops. Do not relay routine status between agents; include required dependency evidence in new briefs. An ordinary request stays in the current task. Separate tasks, durable goals, heartbeats, subscriptions, and recurring monitors require explicit lifecycle authority. Without event support, use bounded live-state reads at checkpoints, not a hidden scheduler.

#### Topology

- **One owner per PR.** The owner is the only writer of its branch and carries the PR from build to merge. Only that owner writes or rebases the branch. The parent performs authorized external writes, including pushes, retargets, and merges, unless the user explicitly assigns them elsewhere. No role can grant itself publication or merge authority. Closing or retargeting a base PR orphans every PR above it, so the owner does that only on your call. You never author or edit code. Conflicted merges, chain rebases, and fixes go to owners.
- **A fresh worker for each independent task.** Its kickoff carries everything it needs, including each upstream report it depends on, pasted in full. Workers can't see their siblings. Prove exclusive paths, separate worktrees, or separate output directories before writable fan-out. Select an authorized surface that has the needed simulator, app control, or credentials. Use only supported task-history APIs, never private transcript stores. Inherit the parent model and reasoning effort unless the user or a validated profile requests another available pair. Keep model and effort separate and distinguish requested configuration from observed served identity.
- **A sub-coordinator only when one area has many parallel workers.** It owns that area's workers and kickoffs and sends you one rollup, never raw worker reports. Stop at three levels: you, sub-coordinators, and workers. Cap in-flight workers at observable runtime capacity, queueing excess lanes without silently dropping them, and start the next one as each finishes instead of waiting on a whole batch.
- **Transfer and verify the built state when new work needs it,** such as a checkout or uncommitted changes. Use a supported fork only when it actually preserves that state; otherwise name the exact artifact and head SHA in a fresh brief. Use supported read-only status or history surfaces to check progress. Some task-message tools start a new turn in an idle task, so use those only for an intentional follow-up on the same work; an informational native-agent message is not a new task.
- **Each PR gets a verifier that isn't its author,** preferably on a different observable model family. If that is unavailable, use an independent inherited-model verifier and report reduced diversity; never claim family diversity from configuration alone. An authorized merge requires the verifier's pass at the current head and the parent's review of its evidence.
- **Start with one unit.** Take it through kickoff, owner, verifier, and authorized merge (or verified handoff when landing is not authorized) before you fan out, so a flaw in the kickoff costs one agent instead of fifty. On near-identical cheap units, the first unit is that test.

#### Supervision

- **Each kickoff names the evidence that proves the work is done,** such as a command and its expected output, a control-skill check, or an artifact. It also names the goal, the paths the worker may and may not write, and the actions it must not take. If you can't name the evidence, the unit isn't scoped yet.
- **Read the diff or the artifact, not only the worker's summary.** Green CI is an input to a verdict, not a verdict. Behavioral work needs more than a type check. A verdict covers one head SHA, so a new push needs a new verdict. Read a sample of each sub-coordinator's kickoffs while its workers run, and fix its instructions when one fails.
- **Send back work that drifts from scope or grows past what was asked.** Keep only the fixes that block the program, and park the rest as follow-ups.
- **Check a PR's live state before you report on it,** with `gh pr view` and `gh pr checks` or your forge's equivalents, not the worker's last report. Account for every worker you spawned as done, replaced, or absorbed into another worker's scope.
- **Stop or replace a worker that stalls or loops.** Judge it by its pushes and PR activity, not its status text. Retry by cause: a smaller scope after a context or memory limit, the same kickoff after a dropped connection, and a different model after a tool error. After two retries for distinct non-interruption failures, drop the unit and replan around it. A child interruption follows the stricter runtime contract: reconcile partial writes, allow at most one bounded replacement, and report a repeated interruption as a gap. When a stopped worker returns late, check its result against the PR's current state, and hand any unique findings to a fresh worker.
- **Ask the user for required permission, a real decision, or a blocker,** such as an irreversible action, a product or preference call that no experiment settles, or a dead end that survived a replan. Rebase mechanics, retries, CI flakes, review triage, and "should I keep going" are normally handled within existing authority. A runtime or policy confirmation still takes precedence.

**Reply:** what landed against the goal, each PR's live state and verdict with its link, what was dropped and why, and the decisions waiting on the user.

If nested agents are unavailable, flatten the queue. If subagents or safe isolation are unavailable, use `sequential-parent`; if independent verification cannot run, report the gap and fail closed on landing. After a restart, reconcile commits, PR heads, artifacts, and supported live status before replacements. A late worker cannot overwrite newer work.
